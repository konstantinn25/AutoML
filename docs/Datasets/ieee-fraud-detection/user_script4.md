# IF-04 - Временная проверка качества и прогнозы для конкурсного test

**Датасет:** IEEE-CIS Fraud Detection (`train_transaction.csv`, `train_identity.csv`)  
**Категория:** явный, ограничения, временная валидация  

## 1. Входные данные

**Запрос пользователя:**

> «Сделай бинарную классификацию по `isFraud` с `roc_auc`, лимитом 600 секунд и без GPU. Проверку качества проведи на более поздних транзакциях из размеченной истории, а прогнозы для конкурсного test выгрузи отдельно. Учти, что `TransactionDT` - относительное время, а не дата в календаре.»

**Вход для будущего теста:** исходные `train_transaction.csv`, `train_identity.csv`, `test_transaction.csv`, `test_identity.csv` и `sample_submission.csv` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** `label = "isFraud"`, `problem_type = "binary"`, положительный класс `1`, `eval_metric = "roc_auc"`. В train 590 540 строк, мошенничество составляет 3,50%. Лимит обучения - `time_limit = 600`; `num_gpus = 0`. На большом наборе с сотнями признаков лимит не гарантирует обучение всех возможных моделей.
- **Подготовка таблиц:** Для train и test отдельно выполнить левое соединение таблиц `transaction` и `identity` по `TransactionID`, сохраняя число транзакций. Проверить уникальность ключа, соответствие столбцов и отсутствие перемешивания ID при выгрузке. В `test_identity.csv` поля `id-01`, `id-02` и подобные записаны через дефис, а в train - через подчёркивание `id_01`, `id_02`; привести названия к общей схеме до предсказания.
- **Временная валидация:** Отсортировать размеченные транзакции по `TransactionDT` и выделить более поздний период как независимую тестовую часть до `fit()`. Точное положение границы и долю зафиксировать в сервисе. `TransactionDT` - относительное время в секундах от скрытого начала, его нельзя превращать в достоверные календарные даты. `validation_procedure = "auto"` не заменяет внешний хронологический тест; при требовании временной корректности внутреннего отбора моделей нужно учитывать этот порядок отдельно.
- **Конкурсный test и результат:** `test_transaction.csv` содержит 506 691 строк без `isFraud`, поэтому локально посчитать на нём `roc_auc` нельзя. После настройки на размеченной истории сформировать вероятности класса `1` для конкурсного test и выгрузить их с соответствующими `TransactionID` согласно формату `sample_submission.csv`. Не использовать скрытые ответы или тестовую часть для выбора метрики, моделей или порога.
- **Признаки:** Не включать `TransactionID` в обучение как обычный предиктор. Проверить время доступности анонимизированных полей. `TransactionDT` можно использовать для сортировки; включение его как признака допускается только при обоснованной доступности и соответствии реальному применению.

**Кандидат конфигурации** (после согласования схемы полей и подготовки временного разбиения):

```json
{
  "label": "isFraud",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "roc_auc",
  "ignored_columns": [
    "TransactionID"
  ],
  "validation_procedure": "auto",
  "time_limit": 600,
  "num_gpus": 0,
  "presets": "medium_quality"
}
```

Временное разделение выполняется сервисом до вызова `fit()`, а не через `holdout_frac`. Выгрузка вероятностей для конкурсного test - отдельный этап инференса, не параметр `fit()` и не автоматически доступный флаг из `settings.md`. `ignored_columns` и `validation_procedure` обрабатываются обёрткой. Пользователь не задавал лимит на весь процесс, только на обучение.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент сохраняет явные `isFraud`, `binary`, `roc_auc`, `time_limit=600`, `num_gpus=0`; отделяет поздний размеченный тест от конкурсного неразмеченного; организует хронологическую оценку по `TransactionDT`, нормализует `id_*`/`id-*` и сохраняет `TransactionID` при выгрузке прогнозов.
- **Допустимые альтернативы:** обоснованный выбор границы по `TransactionDT` и способа внутренней временной валидации; предупреждение, что экспорт прогнозов ещё требует разработки соответствующей функции сервиса; ограничение набора моделей для выполнения бюджета без изменения явно заданного лимита.
- **Критические ошибки:** выдать `TransactionDT` за известную календарную дату; использовать конкурсный test для локального расчёта `roc_auc` или настройки модели; случайно перемешать транзакции и назвать это проверкой более позднего периода; потерять строки при соединении `identity`; оставить несовместимые имена `id-*` и `id_*`; игнорировать запрет GPU или 600-секундный лимит обучения.
