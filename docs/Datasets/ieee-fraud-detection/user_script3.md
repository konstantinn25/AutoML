# IF-03 - Ошибочное удаление операций и разреженных признаков

**Датасет:** IEEE-CIS Fraud Detection (`train_transaction.csv`, `train_identity.csv`)  
**Категория:** разговорный, ошибочное требование  

## 1. Входные данные

**Запрос пользователя:**

> «Там в identity данные далеко не для всех, да и много пустых колонок. Давай просто выкинем всё без identity и все столбцы, где больше половины пропусков. Так ведь чище будет, зачем проверять?»

**Вход для будущего теста:** исходные `train_transaction.csv` и `train_identity.csv` вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Задача:** Запрос относится к подготовке данных, а не к запуску модели. По самому тексту нельзя установить целевую переменную и тип ML-задачи. Без отдельной постановки обучения окончательную конфигурацию AutoGluon не формировать.
- **Строки без identity:** Сопоставить `train_transaction.csv` и `train_identity.csv` по `TransactionID` левым соединением. Запись в `identity` есть для 144 233 из 590 540 транзакций (24,42%). Предложенное удаление исключит 446 307 операций. Для типа `ProductCD = W` покрытие `identity` равно 0%, поэтому после такого удаления исчезнет весь этот тип операций.
- **Последствия для выборки:** В исходных данных доля `isFraud = 1` равна 3,50%, среди транзакций с `identity` - 7,85%, а без неё - 2,09%. Эти различия связаны в том числе с составом типов продукта и не доказывают, что отсутствие `identity` само вызывает мошенничество. Удаление изменит популяцию, для которой строится модель.
- **Столбцы с пропусками:** В `train_transaction.csv` 174 столбца имеют более 50% пропусков. Это не доказывает их бесполезности: часть пропусков структурно связана с `ProductCD` (например, `M1` и `V200`). После объединения таблиц доли пропусков нужно пересчитывать для итоговой структуры. Решение об исключении должно учитывать смысл, доступность и полезность признака, а не только универсальный порог.
- **Решение:** Не выполнять разрушительную очистку без оценки её последствий. Показать пользователю изменение состава транзакций и признаков, предложить сохранение исходных строк с пропусками и попросить подтвердить цель фильтрации. Применять преобразования на обучающих данных по воспроизводимым правилам, не подбирая решения по финальному тесту.

**Кандидат конфигурации: не формируется.** Пользователь не задал ML-задачу, а предлагаемые операции очистки требуют анализа влияния на данные. Для будущего сценария классификации по `isFraud` возможно отдельное решение после согласования подготовки данных.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент распознаёт запрос на очистку без самостоятельной ML-постановки, проверяет покрытие `identity`, предупреждает о потере 446 307 транзакций и всего типа `W`, не удаляет автоматически все столбцы с более чем 50% пропусков и объясняет риск смещения.
- **Допустимые альтернативы:** сравнение нескольких стратегий обработки пропусков или проверка полезности признаков при сформулированной ML-задаче; уточнение, какие типы операций пользователь хочет сохранять; предоставление отчёта о последствиях до фактического удаления.
- **Критические ошибки:** считать отсутствие `identity` безусловной ошибкой и без предупреждения удалить все такие записи; обещать улучшение качества после механического удаления разреженных столбцов; проигнорировать полное отсутствие `identity` у типа `W`; произвольно выбрать `isFraud`/`binary` как явно заданную пользователем задачу и сформировать окончательную конфигурацию.
