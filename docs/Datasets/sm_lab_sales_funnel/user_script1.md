# SM-01 - Прогноз добавления в корзину после открытия карточки

**Датасет:** SM Lab / Спортмастер (`sportmaster_full_dataset..csv`)  
**Категория:** короткий, момент прогнозирования  

## 1. Входные данные

**Запрос пользователя:**

> «Хочу после открытия карточки товара предсказывать, добавит ли человек его в корзину.»

**Вход для будущего теста:** основной `sportmaster_full_dataset..csv` и приведённый выше текст. Сокращённые версии данных не используются как независимый тест.

## 2. Ручной анализ запроса

Результат извлечения требований из текста:

```json
{
  "goal": {
    "value": "предсказывать, добавит ли пользователь товар в корзину после открытия карточки",
    "status": "explicit"
  },
  "task_type": {
    "value": "binary",
    "status": "inferred"
  },
  "target": {
    "value": "факт добавления товара в корзину после просмотра карточки",
    "status": "explicit"
  },
  "metric": {
    "value": null,
    "status": "unknown"
  },
  "constraints": {
    "training_time": {
      "value": null,
      "status": "unknown"
    }
  },
  "requirements": {
    "prediction_moment": {
      "value": "после открытия карточки товара, до последующих действий",

```

Пользователь описывает бинарный исход и момент применения прогноза. Имя столбца, метрика, длительность наблюдения за последующими действиями и требования к проверке модели не указаны. Бинарная классификация выводится из формулировки «добавит ли». Внутренних противоречий нет.

## 3. Ручное решение и конфигурация

- **Задача и таргет:** По результатам EDA целевой столбец - `add_to_cart_flag`, тип задачи - `binary`, положительный класс - `1`. В полном наборе 1 315 513 из 7 000 000 просмотров имеют `add_to_cart_flag=1` (18,79%). Прогноз строится на этапе открытия карточки, а не после добавления товара в корзину.
- **Признаки:** Использовать только информацию, доступную при показе карточки. Потенциальные кандидаты - устройство, признак авторизации, характеристики и доступность товара, категория, цена и скидка. Для каждого поля требуется подтвердить момент фиксации. `create_order_flag` отражает последующее оформление заказа и не допускается в предикторы. `event_id` - технический идентификатор события, его следует исключить. Сам `add_to_cart_flag` служит меткой, а не входным признаком. `user_id` и `product_id` требуют отдельной проверки роли и обобщающей способности; повторение идентификатора само по себе не доказывает утечку.
- **Разметка и подготовка:** В EDA не определён горизонт, в пределах которого последующее добавление в корзину считается положительным исходом. Перед окончательной постановкой необходимо уточнить правила формирования флагов и убедиться, что отрицательные метки уже окончательны. Из 7 млн записей выявлены 34 повторных `event_id`; их происхождение требуется проверить, а не удалять автоматически. Для эксперимента использовать одну согласованную версию - полный CSV.
- **Метрика:** Пользователь не указал приоритет ложных рекомендаций и пропущенных добавлений. Для базового сравнения допустима `roc_auc`, но она выбирается на этапе конфигурирования, а не извлекается из текста. При практическом применении дополнительно оценивать `precision`, `recall` и поведение выбранного порога.
- **Валидация:** Для будущих просмотров предпочтительно хронологическое независимое разбиение по `create_timestamp`. Данные охватывают 1–21 июня 2024 года; 21 июня представлен неполным днём. Нужно проверить зрелость меток на границе разбиения и влияние повторных пользователей/товаров. Если бизнес-цель - новые пользователи, потребуется дополнительная групповая проверка по `user_id`. Внутренняя валидация AutoGluon также должна соответствовать выбранной постановке.

**Кандидат конфигурации** (условный, после уточнения формирования меток и проверки доступности признаков):

```json
{
  "label": "add_to_cart_flag",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "roc_auc",
  "ignored_columns": [
    "event_id",
    "create_order_flag"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

`ignored_columns` относится к столбцам, оставшимся во входной таблице на момент обучения. Если `event_id` или `create_order_flag` удалены при подготовке, список корректируется. `validation_procedure = "auto"` не гарантирует хронологически корректную внутреннюю валидацию; независимый временной тест организует сервис. `time_limit` задаётся сервисом по умолчанию. Неизвестный горизонт метки и непроверенную доступность признаков нельзя считать автоматически разрешёнными.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент выводит бинарную задачу с `add_to_cart_flag`, положительным классом `1` и прогнозом при открытии карточки; не использует `create_order_flag` и технический `event_id` как предикторы; различает признаки в момент просмотра и более поздние действия; проверяет горизонт целевой метки и предлагает независимую оценку с учётом времени.
- **Допустимые альтернативы:** иная обоснованная метрика бинарной классификации; дополнительное уточнение горизонта метки, стоимости ошибок или доступности признаков; временная и при необходимости групповая проверка; удаление запрещённых столбцов на этапе подготовки вместо `ignored_columns`.
- **Критические ошибки:** использовать `create_order_flag` как признак для предсказания более раннего добавления в корзину; считать `event_id` полезным сигналом без обоснования; выдавать `roc_auc` за явно запрошенную метрику; объявлять сокращённые файлы независимым тестом; игнорировать незрелые отрицательные метки или временные зависимости.
