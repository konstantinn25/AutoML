# SM-04 - Прогноз заказов для новых пользователей с ограничениями ресурсов

**Датасет:** SM Lab / Спортмастер (`sportmaster_full_dataset..csv`)  
**Категория:** длинный, ограничения, групповая и временная валидация  

## 1. Входные данные

**Запрос пользователя:**

> «Мы запускаем модель для новых покупателей, а не для тех, кто уже сотню раз смотрел товары. Хотим предсказывать оформление заказа после просмотра карточки. У нас обычный сервер: четыре ядра CPU, GPU нет, бюджет обучения 600 секунд. Нужны вероятность заказа и сравнение моделей. В исходных файлах встречаются повторные пользователи и товары, так что проверка на случайных событиях меня не устраивает.»

**Вход для будущего теста:** основной `sportmaster_full_dataset..csv` и приведённый выше текст. Идентификаторы пользователей и время событий используются сервисом для построения теста.

## 3. Ручное решение и конфигурация

- **Задача и таргет:** Использовать `create_order_flag` как метку бинарной классификации, положительный класс `1`. В EDA заказ оформлен для 350 303 из 7 000 000 просмотров (5,00%). `add_to_cart_flag` отражает последующее действие и не допускается как признак при прогнозе по просмотру карточки. Сначала подтвердить момент получения остальных полей и горизонт, за который зафиксирован заказ.
- **Ограничения обучения:** Установить `time_limit = 600`, `num_cpus = 4`, `num_gpus = 0`. Лимит AutoGluon относится к `fit()`, а не к чтению 7 млн строк, подготовке дат, разбиению, расчёту прогнозов и таблице результатов. Не гарантировать обработку полного объёма данных за десять минут на четырёх ядрах; при необходимости сообщить об ограничении и согласовать допустимый объём или режим обучения.
- **Признаки и версии:** Для основного эксперимента использовать полный CSV. `event_id` - технический идентификатор, `user_id` нужен для разбиения по пользователям, но не должен становиться средством запоминания пользователей, которых не будет при проверке на новых. Поэтому сохранить `user_id` для логики сервиса и исключить из предикторов. Исключить `add_to_cart_flag`. Признаки товара, устройства, цены и скидки допустимы только при подтверждённой доступности при просмотре. Сокращённые версии не служат независимым тестом и могут содержать другие `user_id` и представления цены.
- **Валидация:** Простое случайное разбиение строк нарушает запрос на проверку новых пользователей. Для независимого теста не допускать пересечения `user_id` между обучением и тестом. Поскольку события датированы 1–21 июня 2024 года, предпочтительно одновременно учитывать хронологию: выделить более поздний период и проверить модель на пользователях, которых нет в обучающей части. Такой тест отражает одновременно новый временной период и новых пользователей; число доступных наблюдений необходимо проверить. Если оба условия совместить нельзя, сообщить об ограничении. Внутренняя валидация AutoGluon также не должна создавать неучтённые пересечения для заявленной цели.
- **Разметка и полнота периода:** 21 июня в EDA неполный день. Горизонт фиксации `create_order_flag` не установлен; нужно проверить, достаточно ли поздние события наблюдались до закрытия окна исхода. Нельзя автоматически считать все незавершённые на момент среза действия отрицательным классом.
- **Метрика и выдача результатов:** Учитывать редкость заказа (5,00%). В качестве предварительной метрики выбора моделей допустима `roc_auc`, с отдельным анализом `precision`, `recall` и порога принятия решения. Метрика пользователем не задана. Для вероятностей использовать `predict_proba` для класса `1`; калибровку проверять отдельно при необходимости. Установить `return_leaderboard = true` в настройках сервиса - это не параметр `fit()`.

**Кандидат конфигурации** (условный, после подтверждения схемы признаков и разработки корректной проверки на новых пользователях):

```json
{
  "label": "create_order_flag",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "roc_auc",
  "ignored_columns": [
    "event_id",
    "user_id",
    "add_to_cart_flag"
  ],
  "validation_procedure": "auto",
  "time_limit": 600,
  "num_cpus": 4,
  "num_gpus": 0,
  "presets": "medium_quality"
}
```

Сервис должен установить `return_leaderboard = true` в отдельных настройках и выдавать вероятность класса `1` через `predict_proba`. `user_id` используется для разделения данных до обучения и не передаётся модели как признак; если он удалён заранее, `ignored_columns` корректируется. `validation_procedure = "auto"` не обеспечивает автоматически групповую и временную внутреннюю валидацию. До запуска следует выбрать её корректную реализацию или явно сообщить об ограничении. `time_limit = 600` не ограничивает все операции сервиса.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент выбирает `create_order_flag`, бинарную классификацию и положительный класс `1`, запрещает использовать `add_to_cart_flag` как ранний признак, учитывает новых пользователей через разбиение по `user_id`, учитывает временную структуру и задаёт `time_limit=600`, `num_cpus=4`, `num_gpus=0`. Для отчёта запрашивает вероятности и `return_leaderboard=true` как настройку сервиса.
- **Допустимые альтернативы:** разные обоснованные способы сочетать групповую и временную проверку без пересечения пользователей; дополнительный запрос о горизонте заказа и доступности признаков; ограничение объёма данных по согласованию с пользователем; иная допустимая метрика при контроле редкого положительного класса.
- **Критические ошибки:** делить на случайные строки и заявлять оценку на новых пользователях; включать `add_to_cart_flag` в ранние признаки; использовать сокращённый файл как независимый тест после обучения на полном; игнорировать ограничение 600 секунд/4 CPU/0 GPU; гарантировать успеть обработать 7 млн событий в 600 секунд; передавать `return_leaderboard` прямо в `fit()` или утверждать, что `validation_procedure=auto` гарантирует корректную групповую проверку.
