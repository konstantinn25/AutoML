# RS-04 - Регрессия с ресурсными ограничениями и временной оценкой

**Датасет:** Rossmann Store Sales (`train.csv`, `test.csv`, `store.csv`)  
**Категория:** явный, ограничения  

## 1. Входные данные

**Запрос пользователя:**

> «Построй регрессию для `Sales`, основная метрика `mean_absolute_error`. На обучение пять минут, не больше двух ядер CPU и без GPU. Проверь на более поздних датах. Потом покажи leaderboard. Только не включай фактическое число покупателей за прогнозируемый день - его заранее никто не знает.»

**Вход для будущего теста:** `train.csv`, `store.csv`, доступный для анализа `test.csv` и приведённый выше текст. Для оценки нужно самостоятельно выделить более позднюю размеченную часть истории, не используя конкурсные ответы.

## 3. Ручное решение и конфигурация

- **Задача и таргет:** Использовать `Sales` из `train.csv` и `regression`. Метрика `mean_absolute_error` соответствует типу задачи. Проверить, что итоговая витрина содержит одну строку на сочетание `Store`, `Date`, а целевой столбец остаётся числовым.
- **Признаки и соединение:** Исключить `Customers`: он отражает фактическое количество покупателей за прогнозируемый день и недоступен при прогнозировании заранее. Использовать календарные признаки и при подтверждении доступности плановые `Open`, `Promo`, праздники и характеристики из `store.csv`. Присоединение справочника выполнить по `Store`, сохраняя число строк. Сведения `Promo2Since*` и `CompetitionOpenSince*` проверить на доступность на соответствующую дату; дата будущего события в справочнике сама по себе не доказывает утечку.
- **Валидация:** Для независимой проверки выбрать более поздние даты из размеченной `train.csv`; границу и состав магазинов зафиксировать. `test.csv` не содержит `Sales`, поэтому не используется для локального расчёта `mean_absolute_error`. Для внутренней валидации AutoGluon также учесть временной порядок. Внешнее разбиение нельзя заменить `holdout_frac` или `validation_procedure = "auto"`.
- **Закрытые дни и пропуски:** Уточнить, прогнозируются все календарные дни или только открытые магазины. Нулевые продажи не являются автоматически ошибками: 172 817 наблюдений с `Open=0` и `Sales=0`. В `test.csv` имеются 11 пропусков `Open`, которые нельзя без проверки интерпретировать как закрытие. Наблюдения `Open=1, Sales=0` требуют диагностики, но не произвольной правки.
- **Ограничения и результат:** Установить `time_limit=300`, `num_cpus=2`, `num_gpus=0`. Учитывать, что исходная история содержит более миллиона строк; лимит пяти минут относится к `fit()` и не гарантирует обучение всех моделей, подготовку данных или расчёт отчёта за то же время. В настройках сервиса указать `return_leaderboard=true`; отчёт получать после успешного обучения через `predictor.leaderboard()`.

**Кандидат конфигурации** (после согласования режима закрытых дней, подтверждения доступных признаков и настройки корректной временной проверки):

```json
{
  "label": "Sales",
  "problem_type": "regression",
  "eval_metric": "mean_absolute_error",
  "ignored_columns": [
    "Customers"
  ],
  "validation_procedure": "auto",
  "time_limit": 300,
  "num_cpus": 2,
  "num_gpus": 0,
  "presets": "medium_quality"
}
```

`return_leaderboard=true` относится к `settings.md` и не передаётся в `fit()`. `ignored_columns` должен ссылаться на столбец `Customers` только если он присутствует в итоговой таблице обучения; если он удалён при построении витрины, поле может быть пустым. Временная независимая выборка и корректная внутренняя валидация обеспечиваются сервисом отдельно от этого JSON. Лимит в 300 секунд не включает подготовку данных и расчёт отчёта.

## 4. Критерии проверки агента

- **Обязательные результаты:** установить `label=Sales`, `problem_type=regression`, `eval_metric=mean_absolute_error`, `time_limit=300`, `num_cpus=2`, `num_gpus=0`; исключить `Customers`; обеспечить поздний размеченный временной тест; отличить `return_leaderboard=true` от параметров обучения; проверить `Store`-соединение, доступность признаков и режим закрытых дней.
- **Допустимые альтернативы:** не использовать `Open` при неподтверждённом будущем расписании; отдельно согласовать модель только по открытым дням или для всех дней; применить иные корректные механизмы внутренней временной валидации; сократить объём/сложность обучения в рамках согласованных ограничений без изменения метрики.
- **Критические ошибки:** использовать будущий `Customers`; проверять качество на `test.csv` без `Sales`; перемешивать даты и называть это проверкой будущих продаж; игнорировать ограничение в пять минут, два ядра CPU или запрет GPU; передавать `return_leaderboard` в `fit()`; считать нулевые продажи ошибками и удалять их автоматически.
