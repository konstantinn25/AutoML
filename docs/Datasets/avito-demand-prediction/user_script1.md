# AV-01 - Прогноз вероятности сделки по объявлению

**Датасет:** Avito Demand Prediction (`train.csv`, `test.csv` и вспомогательные CSV)  
**Категория:** короткий, бизнес-постановка  

## 1. Входные данные

**Запрос пользователя:**

> «У меня есть объявления с текстами и ценами. Можно предсказывать, насколько вероятно, что объявление приведёт к сделке?»

**Вход для будущего теста:** Для будущего теста используются `train.csv`, `test.csv` и приведённый выше текст. При необходимости вспомогательные таблицы доступны для анализа, но не включаются автоматически.

## 2. Ручной анализ запроса

Результат извлечения требований из текста:

```json
{
  "goal": {
    "value": "оценивать, насколько вероятно, что объявление приведёт к сделке",
    "status": "explicit"
  },
  "task_type": {
    "value": null,
    "status": "ambiguous"
  },
  "target": {
    "value": "вероятность сделки по объявлению",
    "status": "explicit"
  },
  "metric": {
    "value": null,
    "status": "unknown"
  },
  "constraints": {
    "training_time": {
      "value": null,
      "status": "unknown"
    }
  },
  "requirements": {
    "input_features": {
      "value": "тексты и цены объявлений",
      "status": "explicit"
    },
    "prediction_moment": {
      "value": null,
      "status": "unknown"
    },
    "probability_interpretation": {
      "value": "оценка вероятности сделки",
      "status": "explicit"
    }
  },
  "conflicts": []
}
```

Пользователь формулирует бизнес-цель, но не называет столбец, метрику или точный момент прогноза. Слова «насколько вероятно» сами по себе не определяют алгоритм классификации или регрессии: тип задачи устанавливается после сопоставления цели с данными.

## 3. Ручное решение и конфигурация

- **Задача и таргет:** В `train.csv` есть числовая цель `deal_probability` со значениями от 0 до 1. Она содержит 18 407 различных значений, в том числе 518 730 значений строго между 0 и 1. Для имеющейся разметки подходит регрессия. Не переводить её автоматически в «сделка / нет сделки» и не объявлять прогноз регрессора откалиброванной вероятностью фактической сделки без отдельной проверки смысла таргета и калибровки.
- **Признаки:** `title`, `description`, `price`, категориальные параметры и сведения об объявлении допустимы при подтверждении их доступности к моменту прогноза. Проверить пропуски `description` (7,73% в train), `price` (5,68%), `param_3` (57,37%) и другие поля. Отсутствие параметров может зависеть от категории. `item_id` исключить как идентификатор. `image` содержит идентификатор изображения, а `image_top_1` - код визуальной категории; в перечисленных CSV нет самих файлов изображений. Не обещать извлечение визуальных признаков из отсутствующих файлов.
- **Дополнительные таблицы:** Для базового эксперимента использовать `train.csv`. `test.csv` не содержит `deal_probability` и подходит для получения прогнозов, но не для подсчёта качества. `train_active`, `test_active` и `periods_*` не присоединять по `item_id`: общих ключей с основными размеченными объявлениями нет. История продавца потенциально полезна только после проверки доступности на момент прогноза и безопасной агрегации.
- **Метрика:** В качестве базовой допустима `root_mean_squared_error`; также можно рассмотреть `mean_absolute_error`. Целевой столбец ограничен интервалом [0, 1], поэтому при выдаче прогноза требуется отдельно проверять корректность диапазона и согласовать обработку выходов за него; нельзя обещать, что стандартная регрессия автоматически возвращает только числа в этом диапазоне.
- **Валидация:** После уточнения момента применения предпочтительна хронологическая оценка по `activation_date`, если задача состоит в прогнозе спроса на объявления, публикуемые позже. Для иных условий применения допустимо отдельно обоснованное разбиение. `validation_procedure = "auto"` не обеспечивает хронологическое внешнее разбиение.

**Кандидат конфигурации** (после подтверждения, что прогнозируется именно `deal_probability`, и определения момента использования признаков):

```json
{
  "label": "deal_probability",
  "problem_type": "regression",
  "eval_metric": "root_mean_squared_error",
  "ignored_columns": [
    "item_id",
    "image"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

`image` исключён из базового варианта, поскольку является ссылочным идентификатором, а не пикселями. При наличии проверенного способа использовать этот столбец решение может измениться. `image_top_1` допускается как существующий код признака при подтверждении его доступности. `time_limit` задаёт сервис. Внешнее временное разбиение и обработка диапазона прогноза не выражаются показанными аргументами `fit()`.

## 4. Критерии проверки агента

- **Обязательные результаты:** найти `deal_probability`, предложить регрессию для числовой цели, не подменять её бинарной классификацией; проверить доступность текстов, цены и категорий; корректно объяснить роль `image`, `image_top_1`, пропусков и `item_id`; не считать `test.csv` размеченным тестом; не присоединять вспомогательные таблицы без проверенных связей.
- **Допустимые альтернативы:** сначала уточнить момент прогноза или смысл требуемой вероятности; выбрать другую обоснованную регрессионную метрику; исключить иные признаки после проверки происхождения; отказаться от дополнительной истории продавцов.
- **Критические ошибки:** сделать бинаризацию `deal_probability > 0` без согласования; считать регрессионные значения автоматически откалиброванной вероятностью фактической сделки; использовать `test.csv` для измерения метрики без истинной цели; утверждать, что `image` содержит готовое изображение; напрямую присоединять `periods_train` к `train` по `item_id`.
