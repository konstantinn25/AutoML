# HC-01 - Оценка риска трудностей с платежами при рассмотрении заявки

**Датасет:** Home Credit Default Risk (`application_train.csv`, связанные исторические таблицы)  
**Категория:** короткий, бизнес-формулировка  

## 1. Входные данные

**Запрос пользователя:**

> «Можно заранее понять по заявке, кому будет трудно возвращать кредит? Решение хотим принимать до выдачи денег.»

**Вход для будущего теста:** исходный `application_train.csv` с целевым столбцом `TARGET` и приведённый выше текст. Связанные таблицы могут использоваться после проверки доступности истории к моменту рассмотрения заявки.

## 2. Ручной анализ запроса

Результат извлечения требований из текста:

```json
{
  "goal": {
    "value": "заранее оценивать, у каких заявителей возникнут трудности с погашением кредита, для решения о выдаче",
    "status": "explicit"
  },
  "task_type": {
    "value": "binary",
    "status": "inferred"
  },
  "target": {
    "value": "трудности с погашением кредита",
    "status": "explicit"
  },
  "metric": {
    "value": null,
    "status": "unknown"
  },
  "constraints": {
    "training_time": {
      "value": null,
      "status": "unknown"
    }
  },
  "requirements": {
    "prediction_moment": {
      "value": "до выдачи кредита, на этапе рассмотрения заявки",
      "status": "explicit"
    },
    "feature_availability": {
      "value": "использовать сведения, известные до решения о выдаче кредита",
      "status": "inferred"
    }

```

Пользователь описывает кредитный риск и момент применения модели, но не называет `TARGET`, метрику или вычислительный бюджет. Бинарный характер исхода определяется по смыслу запроса. Внутри текста противоречий нет.

## 3. Ручное решение и конфигурация

- **Задача:** После сопоставления с данными выбрать `label = "TARGET"`, `problem_type = "binary"`, `positive_class = 1`. В EDA `TARGET=1` означает трудности с платежами, а не обязательно буквальный невозврат всей суммы кредита. Положительных заявок 24 825 из 307 511 (8,07%). Учитывать дисбаланс; не оценивать качество только через `accuracy`.
- **Признаки и момент прогноза:** Начать с `application_train.csv`. `SK_ID_CURR` использовать для связи данных и сохранения соответствия, но исключить из предикторов. Для сведений из `bureau`, `previous_application` и платёжных историй проверить доступность до рассмотрения текущей заявки. Обновления кредитной истории после подачи заявки нельзя без проверки считать допустимыми признаками; EDA выявил 17 записей с `bureau.DAYS_CREDIT_UPDATE > 0`, но не доказал утечку во всех подобных полях.
- **Качество данных:** Проверить код `DAYS_EMPLOYED = 365243` (55 374 заявки, 18,01%) как специальное состояние, не как реальный стаж в днях. Сопоставить его с `ORGANIZATION_TYPE = XNA`; необъяснённые большие доходы не удалять автоматически. В `application_train.csv` много неполных признаков; пропуски могут нести информацию. Различия в заполненности `EXT_SOURCE_1` между train/test требуют внимания при будущем прогнозировании.
- **Метрика и валидация:** Пользователь не задаёт стоимость ошибок. Для начального сравнения моделей допустима `roc_auc`, но это выбор системы, а не извлечённая из текста метрика. Для предварительного независимого тестирования возможно стратифицированное разбиение размеченных заявок при отсутствии доказанной групповой зависимости. Такое разбиение не является проверкой на заявках будущего квартала или гарантией качества на новых физических заёмщиках; абсолютных дат текущих заявок в данных нет.

**Кандидат конфигурации** (условный, для исходной таблицы заявок после проверки доступности признаков и выбора протокола оценки):

```json
{
  "label": "TARGET",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "roc_auc",
  "ignored_columns": [
    "SK_ID_CURR"
  ],
  "validation_procedure": "auto",
  "presets": "medium_quality"
}
```

В этом варианте исторические таблицы ещё не включены. Их добавление требует агрегирования до уровня текущей заявки и проверки момента доступности данных. `ignored_columns` обрабатывается обёрткой. Лимит обучения устанавливается сервисом по умолчанию. `roc_auc` предложена для ранжирования риска и не задаёт порог кредитного решения.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент определяет `TARGET`/`binary` и положительный класс `1` после проверки датасета, распознаёт момент прогноза до выдачи, учитывает дисбаланс и особый код `DAYS_EMPLOYED=365243`, исключает `SK_ID_CURR` как технический идентификатор, не допускает неподтверждённо будущие признаки.
- **Допустимые альтернативы:** другая обоснованная метрика бинарной классификации с пояснением её назначения; построение ограниченной модели только по основной таблице; предложение предварительно агрегировать исторические признаки и уточнить их момент доступности.
- **Критические ошибки:** утверждать, что `TARGET=1` обязательно означает полный невозврат кредита; считать `365243` реальным стажем, использовать `SK_ID_CURR` как обычный идентификатор-скоринговый признак без обоснования, соединять исторические строки без агрегации, выдавать случайное тестирование за проверку будущего квартала либо причинное объяснение риска.
