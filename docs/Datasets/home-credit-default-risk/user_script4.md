# HC-04 - CPU-ограничения, приоритет пропусков риска и важность признаков

**Датасет:** Home Credit Default Risk (`application_train.csv`, связанные исторические таблицы)  
**Категория:** длинный, ограничения, асимметрия ошибок  

## 1. Входные данные

**Запрос пользователя:**

> «У нас всего два ядра CPU и пять минут на обучение, GPU нет. Нужен прогноз вероятности невозврата по `TARGET`, а потом таблица важности признаков. Пропустить неплательщика хуже, чем лишний раз проверить добросовестного клиента. Только не говорите, что важность признака автоматически означает причину невозврата.»

**Вход для будущего теста:** размеченный `application_train.csv` и при необходимости доступные на момент заявки исторические таблицы вместе с приведённым выше текстом.

## 3. Ручное решение и конфигурация

- **Смысл целевой переменной:** По EDA `TARGET=1` означает трудности с платежами, а не подтверждённый окончательный невозврат кредита. Пользователь просит именно вероятность невозврата. Поэтому перед обучением нужно уточнить, подходит ли ему существующая разметка как показатель кредитного риска. Если требуется прогноз полного невозврата, необходима другая целевая переменная. Нельзя выдавать `predict_proba(TARGET=1)` за подтверждённую вероятность окончательного невозврата.
- **Задача и ограничения:** Если пользователь согласовал использование `TARGET`, выбрать `label = "TARGET"`, `problem_type = "binary"`, `positive_class = 1`, `time_limit = 300`, `num_cpus = 2`, `num_gpus = 0`. В EDA доля `TARGET=1` равна 8,07%. `time_limit` ограничивает время `fit()`, а не подготовку данных, расчёт важности признаков и формирование отчёта. На больших исторических таблицах нельзя гарантировать завершение всех операций за пять минут.
- **Метрика и ошибки:** При согласованной разметке пропуск клиента с `TARGET=1` соответствует ложноотрицательной ошибке; требуется уделить внимание `recall` и подбору порога для класса `1`. Численная цена ошибок и допустимый объём дополнительных проверок не заданы, поэтому порог нельзя выбирать произвольно. Для первоначального выбора модели допустима `roc_auc` с отдельным контролем `recall`, `precision` и ошибок при выбранном пороге. Если выбрана `recall` в качестве метрики, требуется объяснить риск чрезмерного числа ложных тревог. Не выдавать `roc_auc` за прямую минимизацию пропущенных клиентов.
- **Данные и валидация:** Начать с `application_train.csv`; технический `SK_ID_CURR` не использовать как признак. Обработать `DAYS_EMPLOYED=365243` как особый код, а не реальную длительность работы; проверить пропуски и сдвиг заполненности train/test. Для базовой проверки подходит стратифицированное разбиение размеченных заявок, если нет подтверждённых временных или групповых зависимостей. Не утверждать, что оно проверяет будущий квартал или полностью новых физических заёмщиков.
- **Вероятности и отчёт:** После согласования смысла таргета использовать `predict_proba` для получения вероятностей класса `TARGET=1` и при необходимости согласовать калибровку и порог для выдачи предупреждений. В настройках сервиса установить `return_feature_importance = true`, а важность признаков рассчитывать через `predictor.feature_importance()` на подходящих данных после обучения. Важность оценивает изменение качества при перемешивании признака и не доказывает причинное влияние на невозврат. Для отчёта нужны дополнительные вычисления сверх лимита `fit()`.
- **Возможность запуска:** `presets = "medium_quality"` - базовое значение проекта. Из-за ограничений CPU и 300 секунд сервис должен проверить выполнимость выбранного режима и при необходимости согласовать ограничение моделей или объёма данных. Не обещать гарантированную точность либо готовый отчёт, не проверив ресурсные и вычислительные ограничения.

**Кандидат конфигурации** (только после подтверждения, что `TARGET=1` подходит для бизнес-цели, подготовки допустимых признаков и согласования способа оценки):

```json
{
  "label": "TARGET",
  "problem_type": "binary",
  "positive_class": 1,
  "eval_metric": "roc_auc",
  "ignored_columns": [
    "SK_ID_CURR"
  ],
  "validation_procedure": "auto",
  "time_limit": 300,
  "num_cpus": 2,
  "num_gpus": 0,
  "presets": "medium_quality"
}
```

До подтверждения соответствия `TARGET` бизнес-цели запуск откладывается. В отдельной конфигурации выдачи результатов сервис должен установить `return_feature_importance = true`. Это не аргумент `TabularPredictor.fit()`. Вероятности класса `TARGET=1` получают через `predict_proba`, а выбор рабочего порога и оценка `recall`/`precision` выполняются отдельно по данным, не использованным для окончательной оценки. `roc_auc` выбрана как вспомогательная метрика ранжирования, а не как прямое выражение приоритета ложноотрицательных ошибок. Обязательный лимит обучения - 300 секунд.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент фиксирует различие между «невозвратом» из запроса и трудностями с платежами (`TARGET=1`) в данных; запрашивает подтверждение пригодности метки до запуска. При согласовании выбирает `TARGET` и класс `1`, устанавливает `time_limit=300`, `num_cpus=2`, `num_gpus=0`, предлагает вероятности класса `1` и `return_feature_importance=true` как отдельную настройку сервиса, учитывает приоритет пропусков положительного класса и не объявляет важность причинным объяснением.
- **Допустимые альтернативы:** запрос другой разметки, если пользователь имеет в виду только окончательный невозврат; обоснованный выбор `recall` как метрики с отдельным контролем ложноположительных ошибок или `roc_auc` с отдельной оценкой `recall` и согласованием порога; уточнение допустимого числа дополнительных проверок; сокращённый режим обучения, если он согласован и сохраняет явные ресурсные ограничения.
- **Критические ошибки:** приравнять `TARGET=1` к окончательному невозврату и запускать обучение без разрешения смыслового расхождения; использовать GPU или больше двух ядер, игнорировать лимит 300 секунд, оптимизировать только `accuracy` без учёта пропусков риска, без основания назначить порог или стоимость ошибки, передать `return_feature_importance` в `fit()` как одноимённый аргумент, выдавать feature importance за доказательство причин невозврата либо включать `SK_ID_CURR` в модель без обоснования.
