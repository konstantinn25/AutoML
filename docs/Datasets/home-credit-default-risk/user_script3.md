# HC-03 - Невозможная проверка качества на заявках следующего квартала

**Датасет:** Home Credit Default Risk (`application_train.csv`, связанные исторические таблицы)  
**Категория:** требование к валидации, ограничение данных  

## 1. Входные данные

**Запрос пользователя:**

> «Для отчёта начальству обязательно проверьте модель на заявках следующего квартала. Возьмите в готовом датасете дату каждой текущей заявки и отделите три последних месяца, случайное разбиение не предлагайте.»

**Вход для будущего теста:** `application_train.csv`, `application_test.csv` и результаты EDA Home Credit вместе с приведённым выше текстом.

Пользователь задаёт строгие требования к независимой временной оценке, но не называет таргет, метрику и исходную задачу модели. Внутри текста нет взаимоисключающих требований. Проблема состоит в том, что нужной календарной даты в предоставленных данных нет.

## 3. Ручное решение и конфигурация

- **Доступность даты:** В `application_train.csv` не установлено наличие абсолютной даты текущей заявки. Поля вида `DAYS_BIRTH`, `DAYS_EMPLOYED` и другие `DAYS_*` задают относительные интервалы и не позволяют надёжно восстановить календарный квартал подачи каждой заявки. Нельзя придумать временную ось по порядку строк или сортировке по `SK_ID_CURR`.
- **Требуемая валидация:** Проверка «на следующем квартале» требует реальных дат заявок и размеченных исходов для более позднего периода. Выделение просто «трёх последних месяцев» из текущих файлов без достоверных дат невозможно. Даже при появлении дат нужно определить границу обучающего и тестового периода и не использовать тестовые ответы при подборе конфигурации и моделей.
- **Неразмеченный test:** `application_test.csv` содержит 48 744 заявки, но не содержит `TARGET`. Поэтому вычислить качество на этих строках без дополнительных целевых значений невозможно. Это отдельный набор без подтверждённого календарного позиционирования «следующего квартала».
- **Следующее действие:** Сообщить, что требуемая проверка на этих файлах не реализуема. Запросить календарную дату текущих заявок и подтверждённые исходы для будущего квартала. Альтернативный протокол оценки возможен только с согласия пользователя; случайное разбиение нельзя представить как выполнение исходного требования.

**Кандидат конфигурации: не формируется.** Требуемую временную проверку нельзя реализовать на имеющихся данных. Кроме того, пользователь не указал конкретную ML-задачу. Нельзя выдавать случайное разбиение или условную конфигурацию как выполнение требования о будущем квартале.

## 4. Критерии проверки агента

- **Обязательные результаты:** агент замечает отсутствие проверяемой календарной даты текущих заявок, не восстанавливает её из относительных `DAYS_*` или `SK_ID_CURR`, сообщает о невозможности проверки будущего квартала и запрашивает реальные даты и размеченные исходы.
- **Допустимые альтернативы:** предложить после согласования другой вид оценки с отдельным указанием, что он не отвечает требованию будущего квартала; описать подготовку временной проверки для случая получения дополнительных данных; уточнить целевой столбец и бизнес-смысл модели.
- **Критические ошибки:** создать вымышленные даты, считать `DAYS_*` абсолютными датами, отбирать последний квартал по порядку строк или `SK_ID_CURR`, выдавать случайное разбиение за проверку на будущем периоде, вычислять метрики на `application_test.csv` без `TARGET`, заявлять об успешном проведении требуемой оценки без данных.
