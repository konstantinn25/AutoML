# AB-03 - Объединение сессий и справочников стран для прогноза при регистрации

**Датасет:** Airbnb New User Bookings (`train_users_2.csv`, `test_users.csv` и вспомогательные CSV)  
**Категория:** длинный, соединение таблиц, утечка  

## 1. Входные данные

**Запрос пользователя:**

> «У нас отдельно sessions.csv и таблица со странами. Давай к пользователю присоединим все его клики и характеристики той страны, куда он в итоге поехал. Прогноз ведь нужен прямо при регистрации, но это не должно мешать.»

**Вход для будущего теста:** `train_users_2.csv`, `test_users.csv`, `sessions.csv`, `countries.csv`, `age_gender_bkts.csv` и приведённый выше текст. Проверяется допустимость объединения таблиц и доступность признаков при регистрации.

Внутреннее противоречие состоит в одновременном требовании раннего прогноза и использовании последующего результата как источника признаков. Реальная структура `sessions.csv` и справочников уточняет, почему предложенное соединение ещё и технически некорректно.

## 3. Ручное решение и конфигурация

- **Цель и единица наблюдения:** Предполагается прогноз `country_destination` на уровне пользователя, то есть одна обучающая строка на `id`. Целевая таблица `train_users_2.csv` содержит 213 451 уникальный `id`. Прямое соединение отдельных событий `sessions.csv` без агрегации размножит строки пользователей и может нарушить независимость обучающих примеров.
- **Журнал сессий:** В `sessions.csv` 10 567 737 событий, ключ пользователя называется `user_id`. Журнал есть лишь для 73 815 из 213 451 пользователей train (`34,58%`), но для 61 668 из 62 096 test (`99,31%`). Отсутствуют абсолютные временные метки отдельных событий; `secs_elapsed` не заменяет их. Невозможно надёжно отобрать только клики, совершённые до регистрации. Наличие `booking_request` тоже не доказывает, что событие доступно в требуемый момент. Полные агрегаты истории использовать нельзя.
- **Справочники стран:** `countries.csv` и `age_gender_bkts.csv` не содержат ключей пользователя `id` / `user_id`. Их характеристики относятся к странам назначения. Соединение с обучающими пользователями по фактической `country_destination` является утечкой: на этапе прогноза страна ещё неизвестна. Кроме того, справочники покрывают 10 стран и не содержат `NDF` и `other`; для последних нет однозначного соответствия.
- **Допустимый вариант подготовки:** Использовать информацию, подтверждённо доступную при регистрации, из пользовательской таблицы. Если впоследствии появятся датированные события и подтверждённое правило получения ранних агрегатов, можно присоединить их по `id` - `user_id`, предварительно свести к одной строке на пользователя. Отсутствие истории не означает отсутствие активности, особенно из-за разницы покрытия между train и test. Любые дополнительные сведения из страновых справочников допустимы только при доказанной доступности без знания целевого класса.
- **Валидация и исход:** При проверке новых пользователей предпочесть хронологическое разбиение по `date_account_created`, исключить `date_first_booking` и проверить зрелость исхода `NDF`. Таргет отражает первое бронирование, а не гарантированно совершённую поездку. Для основной постановки по запросу требуется сначала исключить будущие признаки.

**Кандидат конфигурации: не формируется.**

Указанные пользователем правила объединения не могут применяться для прогноза на момент регистрации. После согласования безопасной схемы подготовки данных возможна конфигурация `country_destination` / `multiclass` с проверенными признаками пользовательской таблицы. Наличие нескольких CSV не превращает их соединение в параметр `fit()` AutoGluon.

## 4. Критерии проверки агента

- **Обязательные результаты:** обнаружить конфликт между ранним прогнозом и последующими сведениями; не соединять характеристики страны по фактической метке; объяснить отсутствие абсолютных временных меток событий; учесть различия покрытия журнала train/test; сохранять одну строку на пользователя и запретить полные сессионные агрегаты в ранней модели.
- **Допустимые альтернативы:** предложить базовую конфигурацию только по подтверждённым регистрационным признакам; запросить датированный журнал ранних событий; предложить изменённый момент прогнозирования с новой схемой тестирования и проверкой доступности признаков; отказаться от соединения справочников до определения безопасного ключа.
- **Критические ошибки:** присоединить страновые признаки по `country_destination` и использовать их как предикторы; считать `secs_elapsed` абсолютным временем события; включить полную историю действий в прогноз на момент регистрации; выполнять join строк событий как независимых пользователей; полагать, что отсутствие записи в `sessions.csv` доказывает отсутствие активности.
