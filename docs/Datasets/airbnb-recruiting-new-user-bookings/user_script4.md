# AB-04 - Многоклассовая модель с ограничениями и проверкой будущих регистраций

**Датасет:** Airbnb New User Bookings (`train_users_2.csv`, `test_users.csv` и вспомогательные CSV)  
**Категория:** явный запрос, ограничения, временная валидация  

## 1. Входные данные

**Запрос пользователя:**

> «Построй многоклассовую классификацию по `country_destination`. Метрика `f1_macro`, обучение 600 секунд, GPU не использовать. На тест отложи пользователей, зарегистрировавшихся позже, и покажи таблицу сравнения моделей.»

**Вход для будущего теста:** `train_users_2.csv`, `test_users.csv` и приведённый выше текст. Независимое тестирование по более поздним датам должно опираться на размеченную часть `train_users_2.csv`, а не на неизвестные ответы конкурсного test.

{
  "goal": {

Пользователь явно задаёт тип задачи, таргет, метрику, лимит времени, запрет GPU и временную проверку. При этом момент построения самого прогноза не определён: регистрационная дата используется для отбора будущей тестовой когорты, но это ещё не подтверждение состава доступных на момент прогноза признаков.

## 3. Ручное решение и конфигурация

- **Задача и параметры:** `country_destination` - столбец `train_users_2.csv` с 12 классами. Установить `problem_type = multiclass`, `eval_metric = f1_macro`, `time_limit = 600`, `num_gpus = 0`. Значения извлекаются явно из запроса. `positive_class` для многоклассовой классификации не устанавливается.
- **Независимая временная проверка:** Разбить размеченных пользователей хронологически по `date_account_created`, сохранив более поздних в test. В EDA показана иллюстративная граница `2014-04-02`: 170 523 пользователя до неё и 42 928 начиная с неё; представлены все 12 классов. Допустим другой обоснованный срез с фиксацией границы и сохранением независимости. Сам `test_users.csv` (62 096 пользователей с регистрацией 2014-07-01–2014-09-30) не содержит `country_destination`, поэтому непосредственно по нему нельзя вычислить `f1_macro`.
- **Зрелость таргета:** `NDF` означает отсутствие первого бронирования в доступных данных. Для исторической проверки более поздних регистраций необходимо подтвердить сопоставимый горизонт наблюдения. Иначе часть ещё не успевших забронировать пользователей может быть ошибочно отнесена к `NDF`. Если зрелость меток подтвердить нельзя, агент должен обозначить ограничение оценки, а не выдавать её за доказательство качества на будущих клиентах.
- **Признаки:** Исключить `date_first_booking` и любые производные от её заполненности: они однозначно отделяют `NDF` от остальных исходов. `id` использовать для связи и контроля пересечений, но не как предиктор. До формирования витрины согласовать момент прогноза. Полные агрегаты `sessions.csv` без временных меток не использовать. Проверить пропуски `age`, специальные `-unknown-` и различия распределений между регистрационными когортами.
- **Внутренняя валидация:** Не считать `validation_procedure = "auto"` гарантией корректного временного разбиения внутри AutoGluon. Обёртка должна организовать допустимую временную стратегию либо сообщить о её неподдерживаемости. Внешний тест не используется для подбора моделей, настроек и порогов.
- **Результат:** Показать сравнение моделей через `predictor.leaderboard()` при `return_leaderboard = true` в `settings.md`. Настройка выдачи результатов не передаётся в `fit()` как одноимённый параметр. Время расчёта отчёта и внешней оценки не входит в `time_limit` обучения.

**Кандидат конфигурации** (условный, после определения момента прогноза, корректного временного разбиения и проверки зрелости `NDF`):

```json
{
  "label": "country_destination",
  "problem_type": "multiclass",
  "eval_metric": "f1_macro",
  "ignored_columns": [
    "id",
    "date_first_booking"
  ],
  "validation_procedure": "auto",
  "time_limit": 600,
  "num_gpus": 0,
  "presets": "medium_quality"
}
```

В настройках сервиса: `return_leaderboard = true`. Эта настройка не входит в JSON обучения. `validation_procedure = "auto"` относится к внутренней валидации и не заменяет выделения поздней тестовой когорты. При удалении служебных и недопустимых столбцов до передачи AutoGluon список `ignored_columns` корректируется. Если корректное временное разбиение или сопоставимость меток обеспечить нельзя, финальная конфигурация не утверждается.

## 4. Критерии проверки агента

- **Обязательные результаты:** установить точные `country_destination`, `multiclass`, `f1_macro`, `time_limit=600`, `num_gpus=0`; выделить размеченный хронологический тест по `date_account_created`; исключить `date_first_booking` и производные; проверить статус `NDF`, момент прогноза и внутреннюю временную валидацию; вынести leaderboard в настройки сервиса.
- **Допустимые альтернативы:** другая обоснованная дата границы или доля поздней когорты; разделение по времени с дополнительной проверкой сдвига признаков; уточняющий вопрос о горизонте бронирования и моменте прогноза; сообщение о невозможности достоверной временной оценки при неподтверждённой зрелости исходов.
- **Критические ошибки:** выполнить случайное разбиение вместо требуемого хронологического; считать `test_users.csv` размеченным и вычислять по нему `f1_macro`; включить `date_first_booking` или признак её заполненности; удалить `NDF` без согласования; игнорировать бюджет или GPU; передавать `return_leaderboard` непосредственно в `fit()`; объявить `validation_procedure=auto` достаточной гарантией временной внутренней валидации.
